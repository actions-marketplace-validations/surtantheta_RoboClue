# RC001: recorded motor units versus the declared robot

The same SO follower coordinate names can carry degrees or calibrated -100..100
values. A dataset-only manifest does not establish whether deployment will
interpret them correctly.

The pinned [SO follower configuration](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/robots/so_follower/config_so_follower.py#L42)
and [motor normalization](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/motors/motors_bus.py#L915-L972)
provide upstream evidence. This rule models the supported motor grids and
robot defaults at LeRobot `146d847`; it does not assert defaults for every release.

```sh
roboclue check DATASET --robot-command 'YOUR_DEPLOY_COMMAND' --require deployment-units
```

Default MCP: `preflight_check` with `source` and `robot_command`. A matching result
names both inferred dataset modes and declared consumer settings. Missing,
ambiguous or unsupported evidence stays UNKNOWN; no robot comparison means no
deployment approval. Policy processors, calibration and physical behavior remain
unassessed.

A mismatch uses `units.joint_mode_mismatch`; related codes and exact profiles are
available with `roboclue advanced rules RC001 --json`. Review the intended robot
and policy units, correct the owned command/config, and rerun the same check.
Do not rescale public data merely to clear the report.

Regression examples: `tests/test_units_manifest.py`, `tests/test_preflight_units.py`
and `tests/test_product_question_routes.py` cover mismatch, corrected settings,
healthy grids and ambiguous/missing evidence. [Detailed scope](../UNITS_MANIFEST.md)
