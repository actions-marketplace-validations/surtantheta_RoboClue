# RC004: delta-target transformation matches declared intent

Subtracting state is meaningful only for the declared quantity and convention.
The rule models pinned [openpi DeltaActions at `215abfb`](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/transforms.py)
and supported saved [LeRobot relative processors at `146d847`](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/processor/relative_action_processor.py).
The supported GR00T saved RELATIVE profile is separately versioned in the catalog.

```sh
roboclue check DATASET --openpi-config pi0_libero --openpi-source-root OPENPI_SOURCE
```

Default MCP: `preflight_check` with these same selectors. The answer is
**delta-transform consistency**. It does not establish repack keys, LeRobot
format/dependency support, camera mapping or native training compatibility.
A documented LIBERO transform must not be removed merely because an inferred
fingerprint resembles a different convention.

`convention.relative_on_incremental` can be ERROR only when the supported declared
intent corroborates the contradiction; inference alone can warn or stay UNKNOWN.
`convention.relative_undecided` and `convention.relative_unmodeled` explicitly
preserve limits. Correct the owned configuration only after confirming the
intended transformation, then rerun the same criterion.

`tests/test_action_conventions.py` covers declared faults, documented exceptions,
healthy absolute targets, unsupported transforms and unverifiable pinned source;
`tests/test_product_question_routes.py` checks the public wording and route.
