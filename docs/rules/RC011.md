# RC011: LeRobot camera-slot order

Registry ID: `LR-CAM-SLOT-SHIFT`.

[LeRobot #5118](https://github.com/huggingface/lerobot/issues/5118) reports that
pi0, pi05 and SmolVLA put present cameras first and append missing-camera blanks.
A missing earlier camera can shift a later camera into its slot. For example,
see the [pinned pi05 method](https://github.com/huggingface/lerobot/blob/77710dee471d5cfb070fad1adc30c8f94dc14757/src/lerobot/policies/pi05/modeling_pi05.py#L1378).
Official PyPI LeRobot 0.6.1 source files are also profiled.

The runtime guard checks actual keys at the native image boundary. The CLI/MCP
checks an exported key declaration against the supplied audited source. Missing
leading/interior cameras are distinguished from lawful trailing padding and
SmolVLA's padding cap. A consistent slot result does not verify camera adequacy,
image contents, calibration or physical identity behind a camera key.

Run `roboclue check actual-cameras.json --fail-on error` or default MCP
`preflight_check(source="actual-cameras.json")`. Restore the genuine camera and
recapture the same boundary. No unmasked fake image is inserted. A native
order-preserving ablation implementation requires its own verification.
See the [integration guide](../PIPELINE_CONTRACTS.md).
