# RC002: Isaac Lab quaternion declarations survive conversion

An HDF5 merge can preserve quaternion numbers while losing the attribute that
tells the reader their order. At the qualified Isaac Lab v3.0.0 revision
`e3f7d9ff`, the [HDF5 reader](https://github.com/isaac-sim/IsaacLab/blob/e3f7d9ff1f5d7f8280de3ece9000b7117f66bcf4/source/isaaclab/isaaclab/utils/datasets/hdf5_dataset_file_handler.py)
uses `format_version`; the inspected
[merge tool](https://github.com/isaac-sim/IsaacLab/blob/c7d50a61689c9e971b37f90a70fd9d4bc3ea9062/scripts/tools/merge_hdf5_datasets.py)
copies only selected attributes. These are primary source references, not an
assertion that every Isaac Lab version has this behavior.

```sh
roboclue check SOURCE.hdf5 --converted EXPORT.hdf5
```

Default MCP: `check_sim_provenance` with `source` and `converted`. The rule compares
supported declarations and per-demo quaternion relations. It does not generally
infer quaternion order from numbers; mounting and original-version assumptions
must remain explicit. A source/export match is not physical or training success.

`isaaclab.conversion_quaternion_order` identifies pair contradictions. A single
unversioned file can instead warn or remain UNKNOWN. Retain the originals, apply
only the evidence-supported correction to a separate owned candidate, and repeat
the same pair comparison. Never stamp mixed-source data as one order by guess.

`tests/test_sim_guards.py` includes dropped attributes, consistent conversions,
undecidable roots, tilted/mixed recordings and bounded reads;
`tests/test_product_question_routes.py` exercises the public command.
