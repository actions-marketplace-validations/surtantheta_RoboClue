# RC005: interrupted recordings must not be resumed as-is

Rows, video and metadata do not become durable in one indivisible operation.
RoboClue compares retained bytes with the pinned LeRobot v3
[writer](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/datasets/dataset_writer.py)
and [metadata](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/datasets/dataset_metadata.py)
semantics at `146d847`.

```sh
roboclue check DATASET --question recovery
```

Default MCP: `check_recording_salvage` with `dataset`. This read-only rule covers
supported standard v3 metadata/paths, footers, row identities and optional video
headers. It does not decode video or recover footerless Parquet pages. Partial
coverage and missing evidence cannot approve the current directory for resume.

`salvage.resume_hazard`, `salvage.file_unreadable` and
`salvage.episode_metadata_missing` identify supported faults. A metadata-only plan
for a separate copy is not an already applied repair. Its excluded episodes are
not instructions to delete originals; recovery candidates remain distinct.
Account for orphan videos and complete any required row rewrite before rechecking
the candidate and intended native reader.

`salvage.metadata_rows_repairable` identifies a complete unique identity ledger
that supports correcting data-file pointers and global row spans in a separate
copy. This checks `index`, `episode_index` and `frame_index`, not the meaning or
validity of all action/state values. The automatic repair gate refuses any
unreadable Parquet, video inconsistency, declared-total mismatch, non-unique or
unordered episode metadata, incomplete frame/length tiling or a run across files.

Refusal does not turn contradictory spans into an exclusion plan.
`salvage.metadata_row_conflict` leaves those row/metadata conflicts unresolved,
with no approved keep/drop or automatic-copy plan. Other findings, including
task/statistics defects, `salvage.video_conflict` and the original directory's
`salvage.resume_hazard`, remain visible and retain their severity and CI exit
behavior. `salvage.row_identity` reports stored-index or frame-order defects;
`salvage.episode_integrity` names independently observed missing rows/metadata.
The report can retain a verified physical prefix as evidence, with the remaining
episodes explicitly unresolved. That evidence does not authorize a copy or
exclusion. Physical row positions, spans, frame order and file pointers must
agree; an agreeing stored `index` alone is insufficient.
Preserve the original episodes and
resolve the ledger before resume. A partially read cohort cannot approve a plan.

Automatic local recovery, explicit recovery and the default MCP tool enable
bounded video-header checks by default. An explicit `--no-video-headers` leaves
video completeness unverified and retains the next header-check instruction.
An incomplete video check also withholds automatic global-span repair.
Header checks do not decode frames. Statistics and native loading remain separate
requirements after a metadata repair; a repair is never blanket training approval.

`tests/test_salvage.py` and `tests/test_salvage_product_truth.py` cover interrupted
rows, shard replacement, healthy prefixes, missing video, future staging and
unsupported layouts. `tests/test_product_question_routes.py` verifies discovery.
`tests/test_compound_review_regressions.py` covers independent errors and CI gates
inside unresolved recordings, physical prefixes, file-local index/span defects
and the indented MCP response bound across path lengths.
