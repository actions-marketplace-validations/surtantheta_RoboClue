# RC007: declared camera keys correspond to dataset identities

A robot can declare `front` while a dataset declares `up` and `side`. A units-only
match cannot answer that separate camera question. The pinned
[feature construction](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/utils/feature_utils.py)
and [bimanual camera prefixing](https://github.com/huggingface/lerobot/blob/146d8474932c8b566717eb2738ba459337ab71c4/src/lerobot/robots/bi_so_follower/bi_so_follower.py)
provide source evidence at LeRobot `146d847`.

```sh
roboclue check DATASET --robot-command 'YOUR_ACTUAL_COMMAND_WITH_QUOTED_CAMERA_MAPPING'
```

Default MCP: `preflight_check` with `source` and `robot_command` or `robot_config`.
The report names the raw/effective declared and dataset `observation.images.*`
sets, plus missing/extra keys. An explicit supported `rename_map` maps raw robot
keys to dataset keys; no policy mapping is guessed.

- Disjoint nonempty identities without an applicable declared mapping produce
  `camera.keys_mismatch` ERROR, strictly a declaration-identity mismatch.
- Partial or empty selections produce `camera.partial_keys` WARNING because
  selecting fewer views can be intentional. Extra views also require review.
- Equal sets produce `camera.keys_consistent` PASS for keys only.
- No explicit camera declaration, unsupported plugins or unreadable evidence
  remain unassessed; a missing comparison cannot become an all-interface PASS.

No policy/checkpoint is needed or executed. Image size, frame rate, joint order,
physical camera identity/calibration and policy view selection remain unassessed.
The dataset does not establish which views a future policy requires, and a key
mismatch is not proof that native inference fails.

Review intended views and the explicit mapping. Change only a source-backed
owned command/config and repeat the same comparison. Do not rename a public
dataset merely to obtain equal sets. `tests/test_robot_contract.py` includes the
fault/correction, intentional partial-view, empty/default, bimanual, malformed,
unsupported and canonical-entry-point controls.
