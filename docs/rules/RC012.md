# RC012 — bounded version and provenance register intake

The shipped register contains twelve independently reviewed version/provenance
and publisher-recipe entries. Each has its own applicability, severity and
evidence limits; this does not declare general framework compatibility.
See the [entry inventory and validation scope](../REGISTER_CATALOGUE_EVIDENCE.md).

`roboclue check provenance-input.json` and the existing default MCP
`preflight_check(source=...)` assess a bounded v1 provenance input. A literal
`--launch-command` (MCP `launch_command`) supplies an explicit observation; a
different captured command remains a conflict and becomes UNKNOWN.

Missing or ambiguous inputs request evidence. Package versions cannot attest
installed source. Literal source hints are capped at WARNING. Independently
validated applicability plus a supported violation is required for ERROR;
claims about source behavior additionally need exact independently verified
source bytes. Publisher recipe differences are capped at WARNING and do not claim an
execution failure.

See [the schema and input contract](../PROVENANCE_REGISTER.md) and
[publisher recipe semantics](../REGISTER_RECIPE_SCHEMA_DELTA.md).
