# RC003: GR00T metadata matches the selected consumer

A shared dataset label does not make GR00T N1.5 and N1.7 loader behavior identical.
This static check retains each profile's own conditions and finding version.
Upstream references are the [N1.5 loader at `4af2b62`](https://github.com/NVIDIA/Isaac-GR00T/blob/4af2b622892f7dcb5aae5a3fb70bcb02dc217b96/gr00t/data/dataset.py)
and [N1.7 loader at `944fe70`](https://github.com/NVIDIA/Isaac-GR00T/blob/944fe70c4fd54e3fcb80a7d7258a328f9c061176/gr00t/data/dataset/lerobot_episode_loader.py).

```sh
roboclue check DATASET --groot-version n1.5 --groot-config-name CONFIG_NAME
```

Default MCP: `preflight_check` with `source`, `groot_version` and the supported
config selector. Missing config, dynamic Python constructs and ambiguous version
selection leave dependent checks unassessed; configuration files are parsed as
text rather than executed. A selected metadata contract without errors is not a
native training compatibility certificate.

Codes such as `groot.format`, `groot.state_slice`, `groot.state_config` and
`groot.video_mapping` preserve existing machine meanings. Each report states the
version and conditions; an N1.5 error must not be interpreted as an N1.7 error.
First select a training config matching the dataset. Only then consider a
source-backed change to a separate owned candidate; do not edit public data to
make an unrelated configuration pass. Recheck with the same selected profile.

`tests/test_groot_contract.py` and `tests/test_groot_contract_n15.py` cover faulty,
healthy, missing and dynamic configurations. The public route is tested in
`tests/test_product_question_routes.py`. [Detailed scope](../GROOT_DATASET_CONTRACT.md)
