# RC008: OpenPI raw input keys match the selected adapter

A dataset can use the correct action convention while the chosen training
adapter asks for keys it does not contain. RoboClue checks the actual selected
configuration's literal repack declaration, including supported constructor
overrides. It keeps this verdict separate from [delta-transform consistency](RC004.md).

```sh
roboclue check DATASET --openpi-config CONFIG --openpi-source-root OPENPI_SOURCE
```

The source witnesses are the pinned [training configurations](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/training/config.py)
and [native RepackTransform](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/src/openpi/transforms.py).
An absent required raw key produces `openpi.raw_key_missing`. Supported matching
keys produce a scoped consistency result; dynamic mappings and RLDS backends
remain unknown. Declared task-prompt injection is identified separately and
does not prove the task content exists.

Choose or supply an adapter matching the dataset. Do not rename public data
merely to clear this finding. The detailed report retains raw keys, mapping,
dataset format and the fingerprint-verified consumer lockfile pin. It does not
certify installed-loader compatibility, image values, a trainable batch or training.

Tests cover Libero, Aloha constructor overrides, LeRobot DROID and unsupported
dynamic/backend cases. [Detailed scope](../ACTION_CONVENTIONS.md) · [Catalog](README.md).
