# RC010: OpenPI pretrained-load selection

Registry ID: `OP-PT-WEIGHTS-UNSET`.

[openpi #804](https://github.com/Physical-Intelligence/openpi/issues/804)
reports a PyTorch fine-tuning configuration using `weight_loader` without
`pytorch_weight_path`. The [pinned trainer](https://github.com/Physical-Intelligence/openpi/blob/3e0325a5e6032a9ab6beef7395fe47ca724980a5/scripts/train_pytorch.py#L442)
selects its pretrained load only when the latter is non-null.

This check uses the actual exported resolved fields, explicit initialization
intent and an exact trainer-file hash. It distinguishes a missing pretrained
path from intentional scratch training, and leaves resume/JAX/unknown source
unassessed. It does not inspect weights or claim that a selected load succeeds.

Run `roboclue check actual-initialization.json --fail-on error` or default MCP
`preflight_check(source="actual-initialization.json")`. The export helper can
include its source context; explicit source overrides remain available and MCP
authorizes all paths. Correct the resolved `TrainConfig.pytorch_weight_path`,
recapture, and repeat the same gate. See the [integration guide](../PIPELINE_CONTRACTS.md).
