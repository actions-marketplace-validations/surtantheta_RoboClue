# RC009: FastWAM image scaling

[LeRobot #5116](https://github.com/huggingface/lerobot/issues/5116) reports image
normalization applied twice. A saved mean/std of 0.5/0.5 followed by the model's
`2*x-1` produces `4*x-3`. RoboClue compares the composed per-camera affine map;
MEAN_STD with mean 0/std 1 is a lawful saved-processor control.

```bash
roboclue check CHECKPOINT --runtime-source-root ACTUAL_LEROBOT_SOURCE --fail-on error
roboclue check CHECKPOINT --runtime-source-root ACTUAL_LEROBOT_SOURCE --runtime-mode training --fail-on error
```

The default MCP call is `preflight_check(source=CHECKPOINT,
runtime_source_root=ACTUAL_LEROBOT_SOURCE, runtime_mode="saved")`. The training
chooser selects `runtime_mode="training"`. These calls retain every generic
checkpoint finding and append the independent image finding. A consistent image
map cannot clear an action, state, config mismatch or missing-file error.

`CHECKPOINT` is a local directory or its `config.json`. Source roots may use a
checkout (`src/lerobot`), site-packages (`lerobot`), or the package directory.
Without an explicit source root, distribution metadata locates an installed
LeRobot without importing its code. If that automatically discovered location is
outside MCP read roots, the image check stays UNKNOWN and generic checkpoint
findings remain available. An explicitly supplied outside path is still refused.
Source symlink loops and filesystem resolution failures are bounded input errors.
The source/mode selectors apply only to local FastWAM checkpoints; unrelated
checkpoints reject an explicit source or nondefault training mode.
Exact profiles cover LeRobot
`77710dee471d5cfb070fad1adc30c8f94dc14757` (46 files) and PyPI 0.6.1 (44 files).
Every Python file in the FastWAM, processor and configs directories, plus policy
factory, train/eval construction and constants, is hashed. This includes
`wan/adapters.py`, `wan/components.py`, and the VAE implementation. A profile is a
claim about these files only, not a claim that an entire Git checkout matches a
commit. Missing, edited or oversized source names its first mismatch and stays
UNKNOWN. Python code from the supplied source is never executed.

The model maps are at [modular.py:1298 and :1319](https://github.com/huggingface/lerobot/blob/77710dee471d5cfb070fad1adc30c8f94dc14757/src/lerobot/policies/fastwam/wan/modular.py#L1298)
in the main profile, and :1065/:1086 in PyPI 0.6.1. Float32 RGB pixels in `[0,1]`
are assumed; the affine absolute tolerance is `1e-6`. Diagnostics say the map
*deviates* from the expected contract, without assuming every deviation is
exactly a second normalization. Explicit native-supported `dtype="float32"`
is supported. Custom steps, reordered chains, invalid native feature-type keys,
missing declared states and unrecognized settings remain UNKNOWN.
Serialized device declarations are bounded to CPU/CUDA/MPS/XPU names with an
optional numeric index; this checks the supported declaration syntax, not device
availability. A null normalizer device retains its native default behavior; a
null device-processor target or unsupported device declaration remains UNKNOWN.

Saved mode covers the saved inference/evaluation processor. It cannot establish
fresh training or resumed training. The native trainer at
[lerobot_train.py:684–704](https://github.com/huggingface/lerobot/blob/77710dee471d5cfb070fad1adc30c8f94dc14757/src/lerobot/scripts/lerobot_train.py#L684)
overrides the normalizer map from `policy.config.normalization_mapping`; fresh
fine-tuning also replaces saved statistics with dataset statistics. Training mode
therefore requires a published `config.json` normalization mapping with
`VISUAL=IDENTITY`, including the native IDENTITY default when VISUAL is omitted
from that mapping, to establish image identity normalization independently of
missing effective dataset statistics. An absent mapping or another visual mode
remains UNKNOWN. Resume overrides
are outside the current check. Model execution and task success remain unassessed.

The first fix is to test VISUAL=IDENTITY in **both** `config.json`
`normalization_mapping` and `policy_preprocessor.json` `norm_map` in a separate
owned copy, preserve state/action statistics, and repeat with the same source and
intended mode. RoboClue does not rewrite the checkpoint. Native source and runtime
identity still need independent verification.

CLI and MCP default answers retain per-camera saved file/value, composed
slope/offset and exact source lines. Structured output retains every image map;
MCP concise mode removes the source-file hash list and retains its digest.
Generic messages and error remedies up to 1,024 characters are retained whole;
longer text is explicitly marked and carries its original length and SHA-256.
The training VISUAL echo is similarly bounded at 80 characters. The complete
checkpoint report remains bound by the concise view's full-report digest.
Independent review and whole-product qualification remain release gates.
